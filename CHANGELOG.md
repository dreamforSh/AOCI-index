## [1.6.0] - 2026-11-21

### Added
- **MCP tool profiles**: `aoci_mcp.py --profile core|sync|full` (or `AOCI_MCP_PROFILE`) trims `tools/list`: `core` keeps the 8 read-only tools (`aoci_overview`, `aoci_query`, `aoci_pack`, `aoci_context`, `aoci_symbol`, `aoci_refs`, `aoci_diff`, `aoci_scan`), about 3.3k tool-definition tokens instead of about 10k for `full`; `sync` adds 14 sync/maintenance tools. Calls to tools outside the profile return `isError` with a hint. The installer gains `--mcp-profile` (appends `--profile <name>` to the registered server's args for every host), and the `aoci-mcp` console script now points at the new `aoci_mcp:main`.
- **Pool bundles carry index metadata**: `pool export` adds a `meta` block (`global_invariants`, `project`, declared `domains`, `glossary` groups, `layer_rules`; reported as `exported_meta`). `pool import` fills only gaps, under the index lock: undeclared Domain codes become a `#Domains:` line, unseen glossary groups a `#Glossary:` line, `#Layer-Rules:` is added only when none exist, and `#Global-Invariants:` is set only while it is still `-`. Bundle text is sanitized to single directive lines; the result is reported as `meta_applied`, and repeated imports change nothing. `refresh_self_pool.py --meta-file` sets the bundle meta; `examples/self-pool.meta.json` now ships invariants, domains, and a bilingual glossary, so the zero-token self bootstrap verifies without undeclared-domain warnings.
- **Retrieval & pack evaluation harness (`eval`)**: New `aoci_core.evalbench` and the CLI-only `eval` subcommand score retrieval and `pack` against task cases (`.jsonl` / `.json` with `task`, `expected[]`, optional `id` / `tags`). It reports `recall@k`, `precision@k`, `MRR` (top 20), `seed_recall`, and `pack_recall`. Expected paths that are not indexed are listed as `unknown_expected` and left out of the scores. `--modes bm25,hybrid` compares modes side by side, and `--min-recall` / `--min-pack-recall` exit 1 below the given thresholds. Packs are evaluated without the working-tree diff, so results are reproducible. `examples/eval/self-eval.jsonl` ships 34 developer-phrased tasks for AOCI-index itself. On the shipped 87-file self-index at `--budget 1000`, the BM25 baseline scores recall@8 0.882, MRR 0.733, and pack recall 0.853.
- **Stale-entry flags on read paths**: New `aoci_core.freshness`. `query`, `context`, and `pack` (CLI and MCP) now check the paths they return against `baseline.json`. An unchanged non-racy `(mtime_ns, size)` costs one `stat`; anything else is confirmed with an LF-normalized SHA-256, so a `touch` alone is never reported. Stale paths appear as `stale_entries: [{path, reason, note}]` (reasons: `modified`, `missing`, `unbaselined`), as `seeds[].stale` in `pack`, and as a `## Stale Entries` section or `! stale:` line in text output. Checks are capped at 200 paths per call.
- **Opt-in hybrid retrieval (`--hybrid`, MCP `hybrid: true`)**: New `aoci_core.hybrid.HybridIndex`, a drop-in for `BM25Index.search_detailed`. It fuses BM25 with a zero-dependency character-trigram TF-IDF cosine channel using Reciprocal Rank Fusion (`w / (60 + rank)`; weights bm25 1.0, trigram 0.5; trigram minimum similarity 0.15). The trigram channel catches word-form mismatches such as `subscribe` vs `subscriptions`. An optional dense channel (`--embed-backend model2vec`, `--embed-model`, or `AOCI_EMBED_BACKEND` / `AOCI_EMBED_MODEL`; install with the new `[embed]` extra) caches unit vectors in `.aoci/.cache/embed/` keyed by the SHA-1 of the entry text. If the dense backend is missing or fails to load, retrieval falls back to BM25 + trigram and reports a warning. Hits gain `channels` (rank in each channel) and `bm25_score`; JSON output gains `retrieval`. On the self-eval set, hybrid keeps recall@8 at 0.882, raises MRR from 0.733 to 0.744, and raises seed/pack recall from 0.853 to 0.882. It fixes word-form misses but not synonym misses. BM25 remains the default.
- **MCP background resource watcher**: Subscribed `aoci://` resources are polled (`stat` only) every `AOCI_MCP_WATCH_INTERVAL` seconds (default 2; `0` disables). Changes made outside the server (CLI `upsert`, Git hooks, editors) now push `notifications/resources/updated` without waiting for the next tool call. Subscribing records a baseline right away, the server's own mutations re-sync it so the same change is never pushed twice, and output writes are serialized behind a lock while reusing the client's last framing.
- **Graph-Pruned Symbol References, Index Doctor & Contract Deltas**: Added `refs` / `aoci_refs` (comment-stripped, word-boundary call-site search over FRAS callers, static imports, and tests), `doctor` / `aoci_doctor` plus `lint --fix` (zero-token dedupe, Size-tier refresh, dangling `R:`/`A:` pruning, optional `--sync-static-r`, hubs & shards sync), `contract_delta(s)` in `prepare-sync` / `diff`, hunk-filtered `touched_hub_sections` in `diff` / `pack`, and opt-in `Stop` hook safe auto-heal (`AOCI_HOOK_AUTO_HEAL=safe` or `--auto-heal`). The MCP server now exposes 29 tools.
- **6-Host Ecosystem Installer (`cursor`, `windsurf`, `vscode`)**: Added `--host cursor | windsurf | vscode` (and expanded `--host all`) in `aoci_core.installer` / `scripts/install.py`, plus `--host cursor` lifecycle hook support in `scripts/aoci_hook.py`.
- **Hub-Aware Semantic Pool**: Added `pool_hubs_by_symbol_sha` in `aoci_core.pool` & `aoci_core.hubs` for zero-token, line-shift-resilient `aoci.hubs.txt` restore across branch switches and `pool export/import` bundles.
- **Subagent Batch Work-Pack & Pending Merge**: Added `batch-pack` / `aoci_batch_pack` (`--with-source`) and `upsert --pending-dir [--clean-pending]` with per-file batch provenance on validation errors.
- **CI-Native Architecture Guard & GitHub Action**: Added `ci-check` / `aoci_ci_check` and root `action.yml`, supporting zero-index CI checkouts, `--pool-bundle`, `--base-rev` PR diff test derivation, SARIF 2.1.0, GitHub Actions workflow annotations, and PR Markdown reports.
- **MCP `2025-06-18` Protocol Enhancements**: Added `roots/list` & `notifications/roots/list_changed` multi-root discovery, `outputSchema` + `structuredContent`, `resources/subscribe` / `notifications/resources/updated`, and `aoci_install_git_hooks`.
- **Optional `tree-sitter` Accelerator & Self-Hosting Seed Pool**: Added optional `aoci-index[treesitter]` AST acceleration (`aoci_core.ts_accel`), interactive HTML/Mermaid `--diff` / `--diff-rev` highlighting, and `examples/self-pool.json.gz`.

### Changed
- **More relevant `pack` seeds**: ranked seeds below 20% of the best seed score are dropped (`pack.SEED_MIN_REL_SCORE`); when the task never mentions tests, T-layer hits are scored at 0.35x (`pack.TEST_LAYER_DEMOTE`) with extra candidates fetched to refill the slots; and L1.5 hub sections are matched with the corpus-wide BM25 IDF (at least 2 informative shared terms) to add or boost a file seed (`reason: hub`). `build_task_pack` exposes `min_rel_score`, `test_demote`, and `hub_fallback`. On the self-eval set at `--budget 2500`, seed/pack recall rise from 0.926/0.956 to 0.941/0.971, test files leaking into non-test packs drop from 0.97 to 0.15 per task, and recall at `--budget 1000` is unchanged. A 30% cutoff was measured and rejected because it lost an expected file. Hub fallback had no measurable effect on this small set.
- **One `query` engine for CLI and MCP**: the new `aoci_core.query_ops.run_query` replaces the duplicated filter/rank/test-impact logic in `cli_read.cmd_query` and `aoci_mcp`'s `aoci_query`, so payloads are identical. Behavior change: a CLI `--search` combined with filters now ranks over the full index with the filter as a candidate set, matching MCP, instead of building a sub-index whose IDF depended on how narrow the filter was.
- **MCP tool registry**: the ~840-line `if name == ...` chain in `call_tool` is now one `_tool_<name>` handler per tool plus `TOOL_HANDLERS`. Tests enforce a 1:1 mapping with `TOOLS_SPEC`.
- **Tests organized by module**: shared helpers moved to `tests/aoci_testkit.py`, and the 3,948-line `tests/test_aoci.py` was split method by method into `test_write_ops`, `test_drift`, `test_pool_restore`, `test_git_ops`, `test_graph_search`, `test_volumes`, `test_parsers`, `test_audit_diff`, `test_hooks`, `test_installer`, `test_mcp_server`, and `test_cli_portability`. The (class, method) set was verified identical before and after (217 tests). The milestone-named regression files are unchanged for now.
- **CI lint, type check, and coverage**: new `lint` (ruff `E9,F,B` + mypy, pinned; config in `pyproject.toml`) and `coverage` (branch coverage, `--fail-under=70`, `coverage.xml` artifact; 75% measured locally) jobs. Releases now need `test` and `lint`. A new `dev` extra pins `ruff`, `mypy`, and `coverage`. The codebase passes both checkers: unused imports removed, a loop-closure in the `Stop` hook bound explicitly, and annotation-only fixes for mypy, which targets 3.10 because mypy 2.x requires it; 3.8 runtime parity stays covered by the CI matrix.
- **Incremental MCP cache refresh**: After a mutating tool call (or any change to `aoci.code.txt` while manifest, meta, and glossary are unchanged), `_MemoryIndexCache` re-applies only changed or removed entries. Invalidation now keeps a `stale` copy of the slot as the base. The new `graph.FrasGraphState` / `update_fras_graph_state()` track per-entry edge contributions with reference counts, and re-derive unchanged entries whose references newly resolve or disappear. `BM25Index.updated()` tombstones old documents (rebuilding once tombstones exceed half of the live documents) and copies only the posting lists it touches. Both are copy-on-write, so concurrent readers keep a consistent view, and both match a full rebuild exactly: graph edges, scores, `n_docs`, and `avgdl` (now computed with `math.fsum`). Changes larger than max(256, 25% of entries), or more than 64 new paths, fall back to a full rebuild. On 10,000 entries, a small edit refreshes in about 16 ms instead of about 1.1 s. `_CACHE.last_refresh` records the refresh mode, time, and delta.
- **Up to ~3x faster CLI & hook cold start**: `scripts/aoci_index.py` now re-exports `aoci_core` lazily (PEP 562 `__getattr__`, same symbol set; lookups resolve live against the defining module). `cli_parser` binds named lazy `cmd_*` dispatchers and builds only the requested subcommand's arguments (`build_parser(only=...)`; `--help`, usage, `choices`, and error text stay byte-identical, with a full-tree fallback for unknown commands). `concurrent.futures` (which pulls in `logging`) is imported only when a thread pool is actually used. Entry points (`aoci_index.py`, `aoci_hook.py`, `aoci_mcp.py` run as scripts) now cache bytecode under a per-user `sys.pycache_prefix` (`%LOCALAPPDATA%\aoci-index\pycache`, `~/Library/Caches/aoci-index/pycache`, or `${XDG_CACHE_HOME:-~/.cache}/aoci-index/pycache`) instead of disabling it. Nothing is written beside the skill sources, and library imports keep `sys.dont_write_bytecode = True`. To opt out, use `AOCI_NO_PYCACHE=1`, `python -B`, or `PYTHONDONTWRITEBYTECODE=1`. An existing `PYTHONPYCACHEPREFIX` and wheel installs are left untouched. Measured on Windows / CPython 3.14 (median of 9 runs): `--version` 395 → 115 ms, `UserPromptSubmit` hook 405 → 160 ms, `scan --fast` 424 → 164 ms, and `query --search` 409 → 145 ms on the 81-file self-index.
- **Deferred MinHash sketches in drift scans**: `compute_drift` now fingerprints with `with_sketch=False` (new keyword on `discover_and_fingerprint` / `inspect_and_fingerprint_one` / `_fingerprint_bytes_norm`). The new `discovery.attach_line_sketches()` computes sketches only for exact-rename targets and, when a deleted baseline entry carries a sketch, for added files. It skips any file whose SHA-256 changed since fingerprinting. Baseline writes (`upsert`, `ack`, `fingerprint_file`, `LiveFileSet`) still persist sketches. A full rehash `scan` of 4,000 unindexed files dropped from 1,009 to 592 ms, including the faster startup.
- **Modular `aoci_core` Split with Full `aoci_index` Facade Compatibility**: Split the monolithic `scripts/aoci_index.py` into unidirectional flat modules under `scripts/aoci_core/` (`git_ops.py`, `discovery.py`, `drift.py`, `write_ops.py`, `diff_brief.py`, `audit.py`, `cli_read.py`, `cli_write.py`, `cli_check.py`, `cli_parser.py`, plus `parse_code_volume` in `shards.py`). `scripts/aoci_index.py` remains a lightweight `<450`-line CLI entrypoint and backwards-compatible facade re-exporting all existing public and internal symbols for `aoci_mcp.py`, `aoci_hook.py`, and external scripts; added `.github/scripts/refresh_self_pool.py --check` for deterministic `examples/self-pool.json.gz` maintenance.
- **Monorepo Scale Optimizations**: Added dual positive/negation union regexes in `IgnoreMatcher`, `O(1)` Python suffix index + single-pass comment stripping in `parsers.py`, zero-stat dangling-ref checks + single-parse `verify`, bucketed `TestImpactIndex`, composite PK row-value SQLite pool lookups, same-thread re-entrant `IndexLock` across `apply-sync`, and per-root locks + short-TTL diff caching in `aoci_mcp.py`.

### Fixed
- **Index writer lock heartbeat & safer reaping**: the holder refreshes `.aoci/.lock` every `stale / 4` seconds, and lock lines now record the hostname. A live same-host PID is no longer reaped after 300 s, only after `hard_stale` (default `stale * 12`); dead PIDs are still reaped at once, and other-host or legacy locks keep the plain age rule. Long `apply-sync` runs can no longer be preempted by a second writer.
- **MCP write targets confined to the repository**: `output`, `sarif_output`, `markdown_output`, pool export `file`, and `pending_dir` with `clean_pending` must resolve inside the root and never under `.git/` (hooks there are executable). `AOCI_MCP_ALLOW_OUTSIDE_ROOT=1` lifts only the root rule; the CLI is unchanged.
- **MCP default root follows new client roots**: when a client re-ran `initialize` with a different `rootUri`, or sent a new `roots/list` whose folders had no index yet, the fallback root stayed on the previous workspace, so root-less calls such as `aoci_init` acted on the old repository. The default is now chosen only from the newly announced roots (an indexed one first, else the first). The test reorganization surfaced this through a changed test order.
- **Glossary parsing**: the meta template's `Syntax:` documentation row and directive lines such as `#Domains:` or `#Layer-Rules:` appended after the `# [Glossary ...]` section were parsed as alias groups, injecting bogus synonyms into BM25 query expansion for every new index.
- **P0 · Project-scope installs no longer self-index**: `ALWAYS_SKIP_DIRS` now also covers `.codex`, `.cursor`, `.windsurf`, `.copilot`, and `.codeium`. `path_skip_reason()` skips `<.host>/skills/aoci-index/` (e.g. `.github/skills/aoci-index/` from `--host vscode --scope project`), and discovery skips any directory that holds an installer manifest (`.aoci-install.json`), including on the `--git-fast` incremental path. The Git discovery cache key now has a `skip_rules` revision, so stale cached tables get rebuilt.
- **P0 · `tree-sitter` accelerator is thread-safe and matches the regex extractors**: parsers are now cached per thread (`threading.local()`) instead of one shared `Parser` used by the 8-worker import-graph pool. The probe is locked, and a grammar that is missing or fails to download is negatively cached once instead of being retried by every thread. JS/TS now covers exported `const`/`let` (arrow components, router instances), CommonJS `require()` / `exports.x =`, dynamic `import()`, `export { a, b as c } [from]`, `export * as ns`, and ambient/overload `function` signatures. Rust now covers `impl`/`trait` methods and inline `mod` bodies. C/C++/C#/Java now recurse through nested namespaces/classes with no depth limit, and Go method labels keep the `func (r *T) Name` form. `.cs` now resolves the `csharp` grammar name used by `tree_sitter_language_pack`. Trees that contain syntax errors fall back to the regex path. `outline_cache.json` is now tagged with the extractor (`regex` / `ts<rev>`), so outlines from the other mode are re-extracted instead of being served stale.
- **Packaging, MCP & Sync Hardening**: Moved `install` into `aoci_core.installer` with embedded wheel `_skill_bundle` (`setup.py`), fixed Windows `%3A` file URIs and thread-safe stdio isolation in `aoci_mcp.py`, synced `aoci.hubs.txt` on `restore`, decoupled `apply-sync --ack-impl-only` + `--ack-path`, added UTF-8 BOM handling across volumes/parsers, and enforced read-only `?mode=ro` SQLite pool queries.
- **P1 · `R`/`O`-layer co-read pairs are no longer reported as dependency cycles**: `audit` / `ci-check` now find cycles on `graph.code_dependency_view()`, which drops only edges where both ends are non-code layers (`R` runtime config, `O` docs). Mutual co-reads such as `pyproject.toml <-> setup.py` or README <-> SKILL.md no longer trigger `AOCI002`. Real code cycles and mixed config <-> code cycles are still reported. Layer-rule checks are unchanged. The self-check `ci-check --root . --pool-bundle examples/self-pool.json.gz --exclude-tests` is CLEAN again.
- **P1 · MCP `2025-06-18` `structuredContent` compliance**: when a tool that declares `outputSchema` succeeds, it now always returns `structuredContent`. `aoci_ci_check` (`markdown` / `github` / `sarif`) and `aoci_batch_pack` (`markdown`) publish their underlying report dict through a per-call side channel; any other non-JSON success text is wrapped as `{"text": ...}`. `_CLIENT_ROOT_HINTS`, `_CLIENT_ROOT_HINT`, and `_SUBSCRIBED_URIS` are now guarded by `_STATE_LOCK`.
- **P1 · `#Domains:` one-line directive**: `parse_declared_domains()` now also accepts `#Domains:` / `#Domain:` lines anywhere in `aoci.meta.txt` or `aoci.txt` (like `#Glossary:` / `#Layer-Rules:`). Codes declared by a directive override the `# D (Domain ...)` section on conflict.
- **P1 · VS Code global MCP path**: `--host vscode --scope global` now writes to the VS Code user settings dir (`%APPDATA%/Code/User/mcp.json`, `~/Library/Application Support/Code/User/mcp.json`, `${XDG_CONFIG_HOME:-~/.config}/Code/User/mcp.json`) instead of `~/.vscode/mcp.json`, which VS Code never reads. Install and uninstall also remove the stale `aoci-index` server left in that legacy file. With a sandboxed `--home-dir`, the path stays inside the sandbox.
- **Docs consistency**: README now states the real MCP tool count (29) in all three places, and the unclosed Codex install code block that swallowed the "Cursor, Windsurf & VS Code Copilot" section is fixed. New `tests/test_startup_and_docs_consistency.py` locks tool counts and names (README / SKILL.md vs `TOOLS_SPEC`), balanced Markdown fences, a dated CHANGELOG section for `AOCI_VERSION`, the lazy cold-start import sets, selective-parser equivalence, bytecode cache placement, and deferred sketches.
- **P1 · Docs & metadata**: `SKILL.md` now covers all 6 hosts, all MCP tools (including `aoci_batch_pack` and `aoci_ci_check`), `batch-pack`, `ci-check`, `upsert --pending-dir/--clean-pending`, `export --diff/--diff-rev`, and the `[treesitter]` extra. The SARIF `informationUri` now points to `github.com/dreamforSh/AOCI-index`, matching README / CHANGELOG / the git remote. The `examples/self-pool.json.gz` hashes have been refreshed.

## [1.5.0] - 2026-11-20

### Added
- **OpenAI Codex CLI Support**: Added `--host codex` and `--host all` in `scripts/install.py` and `scripts/aoci_hook.py`, supporting `~/.agents/skills/aoci-index/`, `~/.codex/hooks.json` / `<repo>/.codex/hooks.json` (`SessionStart`, `UserPromptSubmit`, `Stop`), `~/.codex/AGENTS.md` / `<repo>/AGENTS.md`, marker-fenced `[mcp_servers.aoci-index]` in `config.toml`, and manual templates (`resources/codex.hooks.*.json`).
- **Single-Pass Sync Pipeline**: Added `prepare-sync` (`aoci_prepare_sync`) and `apply-sync` (`aoci_apply_sync`) to collect sync briefings, outlines, batched git diffs, and execute `restore -> migrate-renames -> ack -> upsert -> verify` in one orchestrated pass.
- **Cross-File Symbol Lookup**: Added `symbol` / `aoci_symbol` searching across `aoci.hubs.txt`, outline cache (or opt-in read-only `--live`), and FRAS `A:` exports.
- **Git Co-Change & Expanded Language Audit**: Added `audit --co-change [--exclude-tests]` coupling analysis plus JVM (Java/Kotlin), C#, Protobuf, and C/C++ import/outline parsing (with monorepo nested `tsconfig.json` and `go.mod` resolution).
- **CI Release Automation**: Added tag-triggered GitHub Release publishing (wheels, sdists, skill `.tar.gz`/`.zip`, `SHA256SUMS.txt`) and automated changelog generation.

### Changed
- **H-Tier Symbol Sub-Volume (`aoci.hubs.txt`)**: Automatic `hubs` registration in `aoci.txt`, span refresh/pruning during `upsert`, rename migration in `migrate-renames`, and `verify`/`lint` line-bound checks without live re-parsing.
- **Interactive HTML Dependency Export**: Enhanced `export --format html` with direction toggle, pan/zoom controls, focus dimming, and safe `</script>` escaping.
- **Documentation & Visual Refresh**: Streamlined `README.md` with Lucide CDN outline icons and a redesigned no-fill `assets/logo.svg`.

### Fixed
- **Cross-Platform CI & Python 3.8 Compatibility**: Fixed f-string backslash syntax in `scripts/aoci_core/graph.py`, parenthesized multi-context `with` in `tests/test_v16_optimizations.py`, Ubuntu 24.04 Python 3.8 matrix target, missing Git test author config in `tests/test_ext_tests.py`, and canonical `Path.resolve()` keys in `aoci_mcp._MemoryIndexCache`.

- **H-Tier Symbol Zoom**: Added `zoom` / `aoci_zoom` and `.aoci/aoci.hubs.txt` for symbol-level line spans on large hub files.
